# Analysis PC recovery audit (2026-09-22)

The clone contains the code and schedules, not the machine's credentials or
historical data. The analysis PC is `mingo` at `/home/mingo/mingo-computing` on
Ubuntu 24.04. The original user crontab had 73 active lines, including a
per-minute self-reinstaller. Its backup is in
`~/.local/state/dataflow-recovery/20260922T064712Z-audit/crontab.before`.
Setup makes further dated backups under the same private directory.

## What setup restores

- A repository `.venv` with pinned Python packages. The old requirements
  incorrectly named `yaml` and omitted `pyTelegramBotAPI`; the lock uses
  PyYAML, pyTelegramBotAPI, and the kislyuk `yq` wrapper with `jq`.
- Required APT packages, safe empty runtime directories, a small `.bashrc`
  fragment, a dedicated Ed25519 SSH key and config include, a tmux monitor,
  and a restricted swap sudoers rule when administrator access is available.
- Four public station logbook CSVs and the C001 TDC calibration recovered
  from mingo01 with a pinned SHA-256 digest. Setup does not fabricate old data.
- One fixed analysis-PC cron block with 68 commands. The template is
  `CONTEXTUAL/CONFIG/CONTENTS/cron/analysis_pc.crontab`; availability of hosts or secrets
  never changes which lines are installed. The old self-reinstaller and the
  copy from an ignored Copernicus credential path were removed.

## Operational boundary

`setup.sh --apply` installs prerequisites and the fixed schedule, then reports
PASS/WARN/FAIL. `setup.sh --check` gives the same point-in-time report later.
It does not run science processing to assess ongoing health. The scheduled
`OPERATIONS` scripts record command failures in cron logs, collect issue
patterns, write one latest-result CSV per cron job, and write file-flow status
CSVs. The optional full pipeline-state
audit exists under `CONTEXTUAL/OPERATIONS/.../AUDIT_PIPELINE_STATES` but is not scheduled;
its runtime cost should be reviewed before adding it to cron.

The station computers have their own crontabs under
`FOR_MINGO_SYSTEMS/station_automation_scripts`; analysis-PC setup does not
install those. Existing unit tests and shell syntax checks should be run after
any schedule or setup change. A broader pre-existing test suite had seven
failures involving stale plot/QA/gate assertions and the backup shell test had
an old retention expectation; these were not hidden by setup.
