# 2026-11-12 — MINGO01 TRB3sc trigger audit

## Scope and safety

Read the TRB3sc trigger documentation and inspected the active trigger configuration on `mingo01` over SSH. All remote inspection was read-only: no trigger registers, scripts, or other files were changed on `mingo01`.

## Configuration checked

The live register readback matched the installed startup and trigger scripts:

- `0xa138`–`0xa13b` read `0x00050003`, `0x00050005`, `0x00050006`, and `0x0005000c`. These configure plane coincidences 1&2, 1&3, 2&3, and 3&4 with the 50 ns window documented in the trigger script.
- `0xa13d`–`0xa140` read `0x22`, `0x23`, `0x24`, and `0x25`, matching the four plane trigger routes.
- `0xa101` read `0xffff3c00`, matching the OR selection of the four coincidence outputs in the default M3 trigger.
- `0xdf00`, `0xdf04`, `0xdf08`, `0xdf0c`, and `0xdf0d` read `0x000003fc`, `0x0003fc00`, `0x03fc0000`, `0xfc000000`, and `0x00000003`, respectively, matching the configured eight-input group for each plane.

The active cron wrapper temporarily selects self-trigger plus M3 at minute 17 of each hour, waits 60 seconds, then restores M3. The observed register snapshot was the normal M3 configuration.

## Assessment and limitation

The live register state is consistent with the installed configuration and the simulation's configured coincidence set (12, 13, 23, 34). This audit gives no evidence that a different trigger code is needed or that one of the configured coincidence combinations is missing.

Register readback confirms the programmed channel groups and logic, but does not prove the physical mapping from TRB inputs to RPC strips. Crossed patch-panel or detector cabling remains possible and requires an independent wiring-map review or controlled pulser/scaler measurement. The next useful check for a suspected channel swap is to compare per-input rates/responses with known physical strips, then update the mapping model only if that measurement supports it.

## TT12 channel-pattern and permutation follow-up

The channel-level scans in `PIPELINE/MINGO_COMPARISONS/MINGO_SIMULATION_VS_DATA/TT12_CHANNEL_MAPPING_AUDIT/` were extended to test cross-plane endpoint reassignment. The earlier scans had already covered all 225 nonempty strip-mask pairs and all 65,025 pairs of endpoint masks within the existing P1/P2 groups. The new scan evaluates all 6,435 unique balanced partitions of the 16 endpoint inputs into two groups of eight, applying an OR within each group and requiring a coincidence between groups. It uses exact recorded TT12 events from one MINGO01 data file and four MINGO00 simulations; the simulation generated position/direction sidecars are joined by `event_id`.

With the data sample held fixed, the installed grouping has median Jensen–Shannon distance 0.09028 across fitted theta, phi, x, and y. The best reassignment scores 0.08967, a small 0.00060 reduction, while retaining 99.37–99.54% of each simulation sample; it retrospectively passes 93.07% of the recorded data sample. Applying the same pattern to both data and simulation gives a much lower unrestricted score (0.06721), but it retains only 66.99% of data versus 98.62–98.97% of simulation. When requiring data and simulation acceptance to agree within two percentage points, the best score is 0.08880, only 0.00147 below the nominal 0.09028.

These shape-only improvements do not establish a better trigger mapping: the strongest apparent match relies on unequal data/simulation selection, while acceptance-matched candidates improve only slightly and have complicated mixed-plane channel groups. No tested channel mask or balanced endpoint permutation provides a compelling explanation for TT12. These are retrospective selections on events already recorded by the installed trigger; they cannot recover events that trigger rejected. Physical wiring still needs independent confirmation from a cabling map or known-input pulser/scaler measurements. No remote or task-script code was changed.

## Leave-one-trigger-input-out check

To test whether a plane OR might contain only seven of its eight endpoint inputs, I evaluated each single-endpoint omission, omission of both ends of each strip, and combinations omitting one endpoint in each of P1 and P2. The scan used exact `tt_task0_acq == 12` events and the inclusive pool of recorded trigger classes containing planes 1 and 2, with simulation truth sidecars joined by `event_id`.

For the specific example P2S4 front, removing that endpoint from the P2 OR would reject only 7 of 8,647 exact-TT12 data events (0.081%) and 1–2 events per simulation (0.007–0.014%). On the inclusive pool it rejects 9 of 21,783 data events (0.041%) and 3–8 events per simulation (0.010–0.026%). The exact-TT12 shape score remains 0.09028; the inclusive score changes slightly from 0.05805 to 0.05807. This endpoint omission does not explain the broad discrepancy.

Removing both P2S4 endpoints rejects 17.8% of exact-TT12 data, versus 1.3–1.4% of simulation. The paired exact-TT12 score improves only from 0.09028 to 0.08923, and the inclusive-pool score worsens from 0.05805 to 0.07391. This points to differing P2S4 occupancy in data and simulation, not a stable trigger-pattern fix. The live plane-2 CTS input mask `0x0003fc00` has all eight configured bits set. Physical continuity and the input-to-strip cable map are not verified by register readback.

The complete output is `tt12_omitted_channel_scan.csv`, with simulation sidecar truth summaries in `tt12_omitted_channel_truth.csv`, under the TT12 channel mapping audit directory.

## MINGO02 cross-check

The same audit was run on MINGO02 file `mi0226309011801` against its four geometry-matched MINGO00 simulations (`mi0007233000000`, `mi0007253000000`, `mi0007208000000`, `mi0007239000000`; z = [0, 145, 290, 435] mm). These are poor efficiency matches: the recorded robust-efficiency distances are 0.69–0.83.

The broad response discrepancy is also present, more strongly than in MINGO01. In exact TT12, MINGO02 data strip activity is 17.1–36.6%, compared with 67.0–74.7% in simulation. Data P1×P2 strip-pair fractions span 2.7–15.2%; simulation cells span 46.1–54.1%. Across the full raw samples, the topology endpoint mask reproduces the trigger class containing planes 1 and 2 with 100% agreement for MINGO02 data and all four simulations. P2S4 front's mask bit agrees with positive raw endpoint charge in 99.9855% of exact-TT12 data and 100% of simulation.

Removing only P2S4 front rejects 53 of 6,884 exact-TT12 data events (0.77%) and 2–3 events per simulation (0.015–0.024%); the paired shape score remains 0.08362. Removing both P2S4 endpoints rejects 20.25% of data versus 1.19–1.45% of simulation and worsens the score from 0.08362 to 0.09083. The endpoint-level omission is too small to explain the broad discrepancy, while the whole-strip omission has unequal acceptance and makes the shape comparison worse. Same-plane Qsum/Tdif shape distances also do not produce a stable strip permutation.

So MINGO02 shows the same data/simulation response problem, but does not support the specific missing-P2S4-front hypothesis or a simple strip swap. Its lower data activity is substantial, and the available simulations are not close in efficiency, so detector efficiency/response remains a major confounder. Detailed outputs are in the `mingo02_tt12_*` files in the TT12 channel-mapping audit directory. No task scripts or remote trigger settings were changed.

## Full TT-class proportions

I counted the complete raw Task 1 `tt_task0_acq` class composition, using all recorded rows for each data file and the four corresponding simulations. These are within-sample fractions, not exposure-normalized rates: each data sample is one file with a different duration/exposure from the 50,000-event simulation files.

| Measure | MINGO01 data | MINGO01 simulations | MINGO02 data | MINGO02 simulations |
| --- | ---: | ---: | ---: | ---: |
| Exact TT12 / all recorded events | 27.54% | 28.08% (27.25–28.80%) | 23.47% | 26.00% (25.48–26.55%) |
| All classes containing planes 1 and 2 / all events | 69.39% | 58.25% (54.68–62.17%) | 44.58% | 38.65% (37.88–39.92%) |
| Exact TT12 / classes containing 1 and 2 | 39.70% | 48.39% (43.83–52.67%) | 52.66% | 67.30% (64.31–69.55%) |
| TT1234 / all recorded events | 17.40% | 8.23% (6.03–10.66%) | 9.12% | 3.12% (2.54–3.89%) |
| TT23 / all recorded events | 11.44% | 20.29% (18.52–21.68%) | 15.22% | 21.36% (20.38–22.22%) |

The dominant shift is toward higher plane multiplicity in the data. For MINGO01, two-/three-/four-plane classes are 50.67%/31.93%/17.40% of data versus simulation means 62.38%/29.39%/8.23%; mean multiplicity is 2.667 versus 2.458. For MINGO02 those fractions are 66.11%/24.77%/9.12% versus 77.93%/18.95%/3.12%, with mean multiplicity 2.430 versus 2.252. The four-plane TT1234 class is elevated in both data samples, while TT23 is depleted.

As a consistency check, for every full raw sample and each of the four planes, the corresponding 8-bit endpoint-mask OR exactly matches whether that plane digit appears in `tt_task0_acq` (100% agreement). So the class-proportion shift is present in the stored plane-activity masks themselves, not a mismatch between those masks and the recorded class code. This still does not establish physical cabling. The all-class composition Jensen–Shannon distances are 0.101–0.186 for MINGO01 and 0.106–0.145 for MINGO02. The next useful comparison is conditional: inspect per-plane activity and reconstructed/generated angles separately within TT12, TT23, TT123, TT1234, and the other classes. That will show whether the elevated multi-plane fractions come from different event geometry or from detector response/correlation. The four MINGO02 simulations remain poor efficiency matches.

The full class tables and the plot `tt_class_proportions_comparison.png` are in the TT12 channel-mapping audit directory.
